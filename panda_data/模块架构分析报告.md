# panda_data 模块架构分析报告

## 一、模块职责和功能概述

### 1.1 核心定位
`panda_data` 是一个**统一的数据访问层（Data Access Layer, DAL）**，为整个量化分析系统提供标准化的数据读取接口。它封装了底层 MongoDB 数据库操作，向上层业务逻辑提供简洁、高效的数据访问能力。

### 1.2 主要功能模块

#### 1.2.1 市场数据读取（Market Data）
- **日级市场数据**：股票的开盘价、收盘价、最高价、最低价、成交量等基础交易数据
- **分钟级市场数据**：股票的分钟级交易数据，支持亿级数据查询
- **股票基本信息**：股票代码、名称、上市日期等元数据

#### 1.2.2 因子数据读取（Factor Data）
- **基础因子**：系统预定义的因子（open、close、volume、market_cap、turnover、amount）
- **自定义因子**：用户创建的公式因子和 Python 类因子
- **因子持久化**：支持从持久化表直接读取已计算的因子数据

### 1.3 设计理念
- **统一接口**：通过 `__init__.py` 提供统一的函数式接口，隐藏底层实现细节
- **懒加载初始化**：使用模块级全局变量和 `init()` 函数实现延迟初始化
- **性能优化**：采用并行查询、分块处理、缓存等策略提升查询性能

## 二、数据读取接口设计

### 2.1 接口层次结构

```
panda_data (统一入口)
├── init()                          # 模块初始化
├── get_market_data()               # 日级市场数据
├── get_market_min_data()           # 分钟级市场数据
├── get_factor()                    # 基础因子数据
├── get_custom_factor()             # 自定义因子数据
├── get_factor_by_name()            # 按名称获取因子
├── get_all_symbols()               # 获取所有股票代码
├── get_stock_instruments()         # 获取股票基本信息
└── get_available_market_fields()   # 获取可用字段列表
```

### 2.2 接口设计特点

#### 2.2.1 函数式接口
- **优点**：使用简单，无需实例化类
- **缺点**：全局状态管理，不利于多配置场景

#### 2.2.2 参数标准化
- 日期格式统一为 `YYYYMMDD` 字符串
- 支持单个值或列表的灵活输入
- 提供合理的默认值（如 `indicator="000985"` 表示全A股）

#### 2.2.3 返回值一致性
- 统一返回 `pd.DataFrame` 或 `None`
- DataFrame 索引通常为 `(date, symbol)` 多级索引

## 三、核心类和函数说明

### 3.1 MarketDataReader（市场数据读取器）

**职责**：提供日级市场数据的并行查询能力

**核心方法**：
- `__init__(config)`: 初始化，预加载所有股票代码
- `_chunk_date_range()`: 将日期范围分割成多个小块（默认3个月）
- `_get_chunk_data()`: 查询单个日期块的数据
- `get_market_data()`: 并行查询多个日期块并合并结果

**设计模式**：
- **策略模式**：根据数据类型（stock/future）选择不同的集合和查询逻辑
- **模板方法模式**：`get_market_data()` 定义查询流程，`_get_chunk_data()` 实现具体查询

**性能优化**：
- 并行查询：使用 `ThreadPoolExecutor`（默认8个线程）
- 批量大小优化：根据字段数量动态调整 `batch_size`
- 投影优化：只查询需要的字段

**代码质量评估**：
- ✅ 文档完善，包含详细的中文注释
- ✅ 异常处理：参数验证、空结果处理
- ⚠️ 类型注解不完整：部分方法缺少返回类型注解
- ⚠️ 硬编码：线程数（8）、分块大小（3个月）硬编码

### 3.2 MarketStockCnMinReaderV3（分钟数据读取器）

**职责**：处理亿级分钟数据的查询

**核心方法**：
- `_gen_date_sequence()`: 生成日期序列
- `_get_collection_name()`: 根据日期选择存储表（2025年前用 `stock_market_ticket_zstd`，之后用 `stock_market_ticket_by_golang`）
- `_fetch_single_day()`: 获取单日分钟数据
- `get_data()`: 并发查询多日数据并去重

**设计特点**：
- **分表策略**：根据时间范围选择不同的集合
- **并发查询**：使用16个线程并发查询每日数据
- **去重处理**：基于 `(datetime, symbol)` 去重，保留最新记录

**代码质量评估**：
- ✅ 处理了数据同步异常导致的重复问题
- ✅ 使用 `datetime` 字段进行范围查询（而非字符串 `date`）
- ⚠️ 文档注释较少，缺少详细说明
- ⚠️ `get_all_symbols()` 返回 DataFrame 而非列表，与接口不一致

### 3.3 FactorReader（因子数据读取器）

**职责**：提供因子数据的读取和计算能力

**核心方法**：
- `get_factor()`: 获取基础因子数据
- `get_custom_factor()`: 获取自定义因子（支持持久化读取和动态计算）
- `get_factor_by_name()`: 根据名称获取因子
- `_print_formula_error()` / `_print_class_error()`: 详细的错误诊断

**设计特点**：
- **持久化优先**：优先从持久化表读取，未持久化则动态计算
- **延迟导入**：使用延迟导入避免循环依赖（`MacroFactor`）
- **错误诊断**：提供详细的错误信息，帮助用户定位问题

**代码质量评估**：
- ✅ 错误处理完善，提供详细的错误诊断
- ✅ 支持公式因子和 Python 类因子两种类型
- ⚠️ 代码重复：`get_custom_factor()`、`get_custom_factor_competition()`、`get_factor_by_name()` 有大量重复代码
- ⚠️ 硬编码：股票池代码映射（"000300"→"100"）硬编码

### 3.4 PartitionedMarketDataReader（分区市场数据读取器）

**职责**：使用按年分区的集合提升查询性能

**核心方法**：
- `_get_available_years()`: 检测可用的分区集合
- `_get_market_data_for_year()`: 查询特定年份的数据
- `get_market_data()`: 支持并行查询多年份数据
- `_optimize_dataframe()`: DataFrame 内存优化

**设计特点**：
- **分区策略**：按年分区（`stock_market_2023`、`stock_market_2024`）
- **缓存机制**：内存缓存 + 磁盘缓存（pickle）
- **内存优化**：自动优化 DataFrame 数据类型（float64→float32，int64→int32）

**代码质量评估**：
- ✅ 缓存机制完善，支持内存和磁盘两级缓存
- ✅ 内存优化，减少内存占用
- ⚠️ 当前未被主接口使用（`__init__.py` 中未导入）
- ⚠️ 缓存过期时间硬编码（3600秒）

## 四、数据抽象层设计

### 4.1 统一数据访问接口

**现状**：
- ✅ 通过 `panda_data` 模块提供统一的函数式接口
- ✅ 所有接口返回统一的 `pd.DataFrame` 格式
- ⚠️ **缺少抽象基类**：各个 Reader 类之间没有统一的接口定义

**建议改进**：
```python
from abc import ABC, abstractmethod

class DataReader(ABC):
    """数据读取器抽象基类"""
    
    @abstractmethod
    def get_data(self, **kwargs) -> Optional[pd.DataFrame]:
        """获取数据"""
        pass
    
    @abstractmethod
    def get_all_symbols(self) -> List[str]:
        """获取所有股票代码"""
        pass
```

### 4.2 数据访问模式

#### 4.2.1 当前模式
- **直接访问**：直接操作 MongoDB 集合
- **查询封装**：通过 `DatabaseHandler` 封装 MongoDB 操作
- **结果转换**：统一转换为 pandas DataFrame

#### 4.2.2 数据流
```
MongoDB Collection
    ↓
DatabaseHandler (单例)
    ↓
Reader Classes (MarketDataReader, FactorReader, etc.)
    ↓
panda_data Module (统一接口)
    ↓
Business Logic
```

### 4.3 数据一致性

**问题**：
- ⚠️ 不同 Reader 返回的 DataFrame 格式不完全一致
  - `FactorReader.get_factor()`: 返回普通 DataFrame，索引为 `(date, symbol)`
  - `FactorReader.get_custom_factor()`: 返回多级索引 DataFrame
  - `MarketDataReader.get_market_data()`: 返回普通 DataFrame

**建议**：
- 统一返回格式规范
- 提供数据格式转换工具函数

## 六、潜在问题或改进建议

### 6.1 架构层面

#### 6.1.1 缺少抽象基类
**问题**：各个 Reader 类没有统一的接口定义，不利于扩展和维护。

**建议**：
```python
class DataReader(ABC):
    """数据读取器抽象基类"""
    def __init__(self, config):
        self.config = config
        self.db_handler = DatabaseHandler(config)
    
    @abstractmethod
    def get_data(self, **kwargs) -> Optional[pd.DataFrame]:
        pass
    
    @abstractmethod
    def get_all_symbols(self) -> List[str]:
        pass
```

#### 6.1.2 全局状态管理
**问题**：使用模块级全局变量管理 Reader 实例，不支持多配置场景。

**建议**：
- 方案1：支持上下文管理器
```python
with panda_data.DataContext(config1):
    data1 = panda_data.get_market_data(...)

with panda_data.DataContext(config2):
    data2 = panda_data.get_market_data(...)
```

- 方案2：返回 Reader 实例而非全局状态
```python
reader = panda_data.create_reader(config)
data = reader.get_market_data(...)
```

#### 6.1.3 接口不一致
**问题**：不同 Reader 返回的 DataFrame 格式不一致。

**建议**：
- 定义统一的数据格式规范
- 提供数据格式转换工具函数

### 6.2 性能层面

#### 6.2.1 连接池管理

#### 6.2.3 查询优化

**输入**：
- 配置对象（通过 `panda_common.config.get_config()` 获取）
